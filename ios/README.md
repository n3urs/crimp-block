# Crimp Block — iOS app & home-screen widget

A thin native shell around the existing web app, plus a WidgetKit widget.

## Why it's built this way

The app is a `WKWebView` pointed at the live site rather than a rewrite. Pushing
to GitHub Pages updates the phone with no rebuild, and there is only ever one
copy of the training logic.

The widget can't run the rules engine — WidgetKit is a restricted SwiftUI
renderer, not a browser, and it can't sign in to Supabase. So the **web app
precomputes a rolling 14-day forecast** and hands it over a
`WKScriptMessageHandler` bridge; the app stores it in a shared App Group and the
widget just reads today's entry.

That forecast stays valid until you log something — and logging requires opening
the app, which regenerates it. So there is no server, no auth in the widget, it
works offline, and **the training logic is never duplicated**.

`pushNative()` in `app.js` is a no-op in a normal browser, so the website is
completely unaffected.

## Layout

    ios/
      CrimpBlock/            the app  (SwiftUI + WKWebView + bridge)
      CrimpBlockWidget/      the widget (WidgetKit)
      Shared/Forecast.swift  the payload model + App Group accessor, in both targets

App Group: `group.uk.co.sullivanltd.crimpblock` — **both** targets need it or the
widget silently reads nothing.

## First run

1. `open ios/CrimpBlock.xcodeproj`
2. Select the **CrimpBlock** target → Signing & Capabilities → set your Team.
   Do the same for **CrimpBlockWidgetExtension**. Xcode will register the
   bundle IDs automatically.
3. Both targets already declare the App Group in their `.entitlements`. If Xcode
   complains it isn't registered, tick **+ Capability → App Groups** and pick
   the existing group.
4. Plug the phone in, pick it as the run destination, hit run.
5. Sign in once in the app. That populates the widget.
6. Long-press the home screen → **+** → Crimp Block → add the widget.

## Notes

- Bundle IDs: `uk.co.sullivanltd.crimpblock` and `…​.widget`. Change both in
  Xcode if you'd rather use something else.
- The widget shows "Open the app to refresh" if the cache has no entry for
  today. That's deliberate — better than confidently showing a stale workout.
- `project.pbxproj` is generated by a script with deterministic IDs, but it is
  now a normal Xcode project; just edit it in Xcode.
